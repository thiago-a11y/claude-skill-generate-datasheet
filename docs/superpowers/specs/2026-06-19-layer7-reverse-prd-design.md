# Layer 7 — Reverse PRD: Design Spec
<!-- generate-datasheet skill · brainstorming session · 2026-06-19 -->

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Where it lives | Layer 7 inside generate-datasheet | Reuses Phase 1 scan data; consistent UX; cross-references Layer 1 docs |
| To-Be strategy | Hybrid (auto As-Is + adaptive interview) | Code shows WHAT, not WHY — targeted questions fill the intent gap |
| ADR format | Hybrid (embedded summary in PRD + separate ADR files) | Summary for quick reading; ADR files for traceability and immutability |
| Flow | Two approval gates (As-Is → gate → interview → To-Be → gate → generate) | Prevents PRD with wrong premises — highest risk identified in research |

## Research Foundation

- Reverse requirements engineering is under-tooled — no reliable code-to-PRD tool exists (market gap confirmed)
- Biggest pain point: code shows WHAT, not WHY decisions were made
- Outdated documentation is worse than none — anti-hallucination is non-negotiable
- ADRs are immutable by design — new decision = new ADR, never edit old ones
- As-Is vs To-Be must be explicitly separated with clear labeling
- Max 10 interview questions — respects developer time, forces prioritization

## Outputs

| File | Content |
|------|---------|
| `docs/prd.md` | Main Reverse PRD — single Markdown file, versionable |
| `docs/decisions/ADR-001-{slug}.md` | One per significant architectural decision (max 5-7) |

## Flow — Phase 9 (Layer 7)

```
Phase 9.1 — Build As-Is
  └─ Consolidate Phase 1 data (no re-scan)
  └─ Reconstruct personas from roles, auth, UI labels
  └─ Map user journeys from routes + components
  └─ Identify implicit constraints (hosting, scale, auth pattern)
  └─ Decision archaeology: git log + code comments

[GATE 1] Phase 9.2 — Present As-Is to user
  └─ Show summary: personas, capabilities, journeys, constraints
  └─ Ask: "Does this reflect what the system does? What's wrong?"
  └─ User corrects → skill incorporates corrections
  └─ Only advances after confirmation

Phase 9.3 — Adaptive interview
  └─ 4 fixed questions (always)
  └─ Up to 6 conditional questions (from detected gaps)
  └─ One question at a time via AskUserQuestion
  └─ Max 10 questions total
  └─ "Skip" = [MANUAL] — never blocks flow

[GATE 2] Phase 9.5 — Present To-Be draft to user
  └─ Show vision, feature roadmap, acceptance criteria
  └─ Ask: "Does this capture the right direction?"
  └─ User corrects → skill incorporates
  └─ Only advances after confirmation

Phase 9.6 — Generate ADRs
  └─ Detect significant decisions with evidence
  └─ Generate max 5-7 docs/decisions/ADR-00N-*.md files
  └─ Mark [INFERRED] where decision was reconstructed

Phase 9.7 — Generate docs/prd.md
  └─ Combine: approved As-Is + approved To-Be + ADR summary
  └─ Count and list all [MANUAL], [VERIFY], [INFERRED]

Phase 9.8 — Final report
  └─ Files generated, strong vs weak evidence sections
  └─ Human input items remaining
```

## Adaptive Interview Questions

### Fixed (always asked, in this order)

| # | Question | Maps to |
|---|----------|---------|
| F1 | Em uma frase: qual problema este produto resolve, para quem? | §1 Problem & Context |
| F2 | Quem é o usuário principal? (cargo, contexto, nível técnico) | §2 Personas |
| F3 | O que foi conscientemente NÃO construído, e por quê? | §3 Scope |
| F4 | Onde este produto deveria estar em 6-12 meses? | §10 Vision |

### Conditional (triggered by Phase 1 findings)

| Trigger | Question |
|---------|----------|
| Multiple auth roles detected | Quais perfis de acesso existem? O modelo de permissão está correto ou é legado? |
| ERP integration detected (SAP, TOTVS, Protheus, Oracle) | Esta integração é bidirecional? Quem é o sistema de registro (master) para cada entidade? |
| >3 external APIs consumed | Quais integrações são core para o produto funcionar vs nice-to-have? Se uma cair, o que quebra? |
| Own API exposed (public endpoints) | Esta API é consumida por terceiros / parceiros / clientes? Existe contrato de versionamento? |
| Service layer / microservices detected | Esses serviços são produtos independentes ou auxiliares deste sistema? |
| Mixed audience in code (admin + end-user) | Quem paga pelo produto? Quem usa no dia a dia? São a mesma pessoa? |
| Multi-tenant detected or expected | O produto é SaaS multi-tenant, multi-instância, ou on-premise por cliente? |
| 0 tests + critical code | Qual a tolerância a downtime em produção? Existe SLA com clientes? |
| >20 TODO/FIXME in critical modules | Existe tech debt deixado intencionalmente? Qual o plano para ele? |
| Single contributor in git | Existe um "guardião" deste projeto? Quem deve herdar o conhecimento? |
| Undocumented modules + high churn | Quais módulos têm regras de negócio críticas que não estão documentadas em lugar nenhum? |
| Legacy stack detected (PHP 5/7, VB, Delphi, .NET Framework) | Existe plano de modernização? Qual o horizonte? |
| Vendor lock-in detected (AWS, Azure, cPanel) | O lock-in com este vendor é intencional ou acidental? |

### Rules
- One question at a time via AskUserQuestion
- Max 10 questions total (4 fixed + up to 6 conditional, most relevant first)
- If F1/F2 answers already cover a conditional question, skip it
- "Skip" or empty answer → recorded as [MANUAL] in PRD, never blocks flow

## Decision Archaeology — Evidence Sources

```bash
# 1. Git messages indicating decisions
git log --all --oneline | grep -iE "chose|decided|instead|replaced|migrated|switched|moved to|refactor|rewrote"

# 2. Code comments with intent
grep -rn "// Note:\|// Reason:\|// Because\|// workaround\|// intentionally\|# NOTE\|# HACK" \
  --include="*.ts" --include="*.php" --include="*.py" --include="*.go" 2>/dev/null | head -30

# 3. Implicit decisions from stack choices
# Express detected → ADR "Express vs alternatives"
# JWT detected → ADR "JWT vs Sessions"
# MySQL detected → ADR "MySQL vs PostgreSQL"
# REST without GraphQL → ADR "REST API strategy"
# No message queue → ADR "Synchronous processing"

# 4. Structural decisions
# Monolith without docker-compose → ADR "Monolith architecture"
# Single DB without read replicas → ADR "Single DB strategy"
```

### ADR Generation Rules
- Only generate ADR if clear evidence exists (git message, comment, or unambiguous code pattern)
- Maximum 5-7 ADRs per project — only decisions with real architectural impact
- Always include `Alternatives Considered: [NOT DOCUMENTED]` if not found in code
- Mark `[INFERRED]` when decision reconstructed from patterns, not explicit docs
- Format is immutable: once generated, ADR never changes — new decisions = new ADR

### ADR Template

```markdown
# ADR-001 — {Decision Title}
<!-- source: {file:line or git commit hash} -->
<!-- confidence: [INFERRED] | DOCUMENTED -->

**Status:** Accepted
**Date:** {date inferred from git or [NOT DETECTED]}

## Context
{What was being decided and why a decision was necessary}

## Decision
{What was chosen, with code evidence}

## Alternatives Considered
{If found in code/git. If not: [NOT DOCUMENTED]}

## Consequences
{What this decision implied — detected in code}
```

## Markers (complete system for Layer 7)

| Marker | Meaning |
|--------|---------|
| `[INFERRED]` | Reconstructed from code patterns — not explicitly documented |
| `[USER-PROVIDED]` | Came from the interview — not from code |
| `[VERIFY]` | Found but purpose uncertain |
| `[NOT DETECTED]` | Searched, not found |
| `[MANUAL]` | Requires human input, cannot extract from code |
| `[PARTIAL]` | Incomplete evidence |

## Anti-Hallucination Rules (Layer 7 specific)

```
WRONG: "O produto foi construído para o mercado B2B"
RIGHT: "Público-alvo: [USER-PROVIDED] — 'vendedores B2B de médias empresas' (resposta Q1)"

WRONG: "A decisão de usar JWT foi tomada por questões de performance"
RIGHT: "JWT detectado em api/auth.php:12. Razão: [INFERRED] — sem sessão server-side
        detectada. Alternativa Sessions: [NOT DOCUMENTED]. Ver ADR-002."

WRONG: "O sistema suporta múltiplos clientes"
RIGHT: "Multi-tenancy: [NOT DETECTED] — nenhum tenant_id, schema separation,
        ou row-level security encontrado. [VERIFY] com equipe."

WRONG: "O roadmap prevê integração com Salesforce"
RIGHT: "Roadmap: backlog.md:15 — 'TODO: integração CRM (indefinido)'.
        Salesforce não detectado no código. [MANUAL — confirmar sistema CRM alvo]"
```

Every claim in the PRD must:
1. Cite its source (file:line, git hash, or interview question number)
2. Use the appropriate marker if uncertain
3. Never assert intent without evidence or user confirmation
