Qual tecnologia usar para o app desktop?

3 abordagens reais para Windows + Mac, com o CodeDocs (Python) rodando por baixo

A

Electron (TypeScript + React)

O app é uma janela de browser que roda local. A UI é feita em React (sua stack atual). O Python do CodeDocs roda como processo filho.

Prós

  • Você já sabe React + TypeScript
  • Maior ecossistema de componentes desktop (VS Code, Slack, Discord usam)
  • Empacota para .exe (Windows) e .dmg (Mac) com electron-builder
  • Renderiza HTML nativo — seus documentos CodeDocs aparecem pixel-perfect
  • PDF export nativo via Chromium (print-to-PDF built-in)

Contras

  • Instalador grande (~150-200MB) porque inclui Chromium
  • Precisa embutir Python no pacote (ou pedir que o usuário instale)
  • Consumo de RAM médio-alto (~200-400MB)

Referências: VS Code, Slack, Discord, Figma Desktop, Postman

B

Tauri (TypeScript + React + Rust)

Como o Electron, mas usa o WebView nativo do SO (Edge/WebKit) em vez de embutir Chromium. Backend em Rust, mas a UI continua sendo React.

Prós

  • Instalador MUITO pequeno (~5-15MB vs 150MB do Electron)
  • Baixo consumo de RAM (~50-100MB)
  • Você ainda usa React + TypeScript na UI
  • Mais rápido para abrir, mais leve para rodar
  • Segurança melhor (sem Node.js no processo principal)

Contras

  • WebView do Windows (Edge WebView2) pode ter inconsistências visuais vs Mac (WebKit)
  • Comunidade menor que Electron (crescendo rápido)
  • Precisa de Rust para o backend — ou usar "sidecar" para rodar o Python
  • PDF export precisa de lib externa (não tem Chromium built-in)

Referências: Cody (Sourcegraph), 1Password (migrou do Electron), Crabnebula

C

Python Nativo (PyInstaller + CustomTkinter ou PyWebView)

App 100% Python. Usa CustomTkinter para UI nativa OU PyWebView para renderizar HTML. Empacota com PyInstaller em .exe/.app.

Prós

  • Sem dependência de Node/npm/React — tudo em Python
  • CodeDocs já é Python — integração direta, sem processo filho
  • PyWebView renderiza HTML nativo (seus documentos CodeDocs funcionam)
  • Instalador pequeno (~30-50MB)

Contras

  • UI menos polida que React (CustomTkinter é limitado)
  • PyWebView tem menos controle que Electron/Tauri
  • Comunidade muito menor para apps desktop em Python
  • PDF export manual (weasyprint/reportlab)
  • Menos exemplos de apps comerciais bem-sucedidos

Referências: Poucos — Calibre (e-book), Frescobaldi (music notation)

💡 Minha recomendação: Tauri (B)

Para um gestor não-técnico, o instalador de 10MB vs 200MB faz diferença real. A UI continua sendo React (sua stack). O CodeDocs Python roda como "sidecar" (processo separado que o Tauri gerencia). O único trade-off é o PDF export, que resolve com uma lib como wkhtmltopdf embutida ou gerando PDF no próprio Python (que você já tem).
