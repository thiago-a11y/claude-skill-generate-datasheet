# Health Badges v1 — Real Metrics for Your README

## What this skill produces

SVG badge files + README snippet. Each badge shows a real metric from the codebase scan, not a vanity number.

### Available Badges

| Badge | What it shows | Color logic |
|-------|--------------|-------------|
| **Health Score** | Composite 0-100 score | green ≥70, yellow ≥40, red <40 |
| **Test Coverage** | Test files / source files ratio | green ≥60%, yellow ≥30%, red <30% |
| **Dependency Freshness** | Packages on latest major / total | green ≥80%, yellow ≥50%, red <50% |
| **Bus Factor** | Min contributors on critical modules | green ≥3, yellow ≥2, red =1 |
| **Doc Coverage** | Documented modules / total modules | green ≥80%, yellow ≥50%, red <50% |
| **Tech Debt** | TODOs+FIXMEs per 1000 LOC | green ≤2, yellow ≤5, red >5 |
| **AI Cost Awareness** | LLM callsites with optimization opportunity | green =0, yellow ≤3, red >3 |
| **Last Scan** | Date of last generate-datasheet run | always blue |

### Output Files

## Process

### Phase 0 — Pre-flight

Ask the user:

```
Which badges do you want?

1. All badges (recommended)
2. Health score only
3. Select specific badges
4. Custom badge (I'll define the metric)

Insert badges into README automatically? (yes / no)
```

### Phase 1 — Metric Collection

Run scans to collect each metric with evidence.

**1.1 — Test Coverage Ratio**
```bash
# Count source files (adapt extensions to detected stack)
find . -name "*.ts" -o -name "*.js" -o -name "*.py" -o -name "*.php" -o -name "*.go" -o -name "*.rs" | grep -v "node_modules\|vendor\|\.test\.\|\.spec\.\|test_\|_test\.\|__test__" | wc -l

# Count test files
find . -name "*.test.*" -o -name "*.spec.*" -o -name "test_*" -o -name "*_test.*" -o -name "*Test.php" -o -name "*_test.go" | wc -l
```

**1.2 — Dependency Freshness**
```bash
# Total vs outdated (adapt to stack)
npm outdated 2>/dev/null | tail -n +2 | wc -l    # outdated count
cat package.json 2>/dev/null | grep -c '"'        # rough total deps

composer outdated --direct 2>/dev/null | tail -n +2 | wc -l
pip list --outdated 2>/dev/null | tail -n +3 | wc -l
```

**1.3 — Bus Factor**
```bash
# Contributors per critical directory
for dir in $(find . -maxdepth 2 -type d -not -path "*/node_modules/*" -not -path "*/.git/*" -not -path "*/vendor/*" | head -20); do
  count=$(git log --format="%an" -- "$dir" 2>/dev/null | sort -u | wc -l | tr -d ' ')
  if [ "$count" -gt 0 ]; then
    echo "$count $dir"
  fi
done | sort -n | head -15
```

**1.4 — Documentation Coverage**
```bash
# Modules (top-level dirs with code)
find . -maxdepth 1 -type d -not -name ".*" -not -name "node_modules" -not -name "vendor" -not -name "docs" | wc -l

# Documented modules (have README or docs referencing them)
find . -name "*.md" -not -path "*/node_modules/*" | wc -l
```

**1.5 — Tech Debt**
```bash
# TODOs + FIXMEs + HACKs
grep -rn "TODO\|FIXME\|HACK\|XXX\|WORKAROUND" --include="*.ts" --include="*.js" --include="*.py" --include="*.php" --include="*.go" --include="*.rs" 2>/dev/null | wc -l

# Lines of code (rough)
find . -name "*.ts" -o -name "*.js" -o -name "*.py" -o -name "*.php" -o -name "*.go" -o -name "*.rs" | grep -v "node_modules\|vendor" | xargs wc -l 2>/dev/null | tail -1
```

**1.6 — AI Cost Awareness**
```bash
# LLM callsites with potential optimization
grep -rn "gpt-4o\|gpt-4\|claude-opus\|claude-sonnet\|gemini-pro" --include="*.ts" --include="*.js" --include="*.py" --include="*.php" 2>/dev/null | grep -v "node_modules\|vendor" | wc -l
```

**1.7 — Last Scan Date**
```bash
# Check when generate-datasheet last ran
ls -la docs/health-score.md docs/architecture.md 2>/dev/null | head -2
date +%Y-%m-%d
```

### Phase 2 — Calculate Scores

For each metric, calculate the value and determine color:

```
Test Coverage:
  value = (test_files / source_files) × 100
  display = "{value}%" 
  color = green if ≥60, yellow if ≥30, red if <30
  evidence = "{test_files} tests / {source_files} source files"

Dependency Freshness:
  value = ((total_deps - outdated_deps) / total_deps) × 100
  display = "{value}%"
  color = green if ≥80, yellow if ≥50, red if <50
  evidence = "{outdated} outdated / {total} total packages"

Bus Factor:
  value = minimum contributors across critical modules
  display = "{value}"
  color = green if ≥3, yellow if ≥2, red if =1
  evidence = "lowest: {module} ({value} contributors)"

Doc Coverage:
  value = (documented_modules / total_modules) × 100
  display = "{value}%"
  color = green if ≥80, yellow if ≥50, red if <50
  evidence = "{documented} / {total} modules documented"

Tech Debt:
  value = (todo_count / (loc / 1000))
  display = "{value}/KLOC"
  color = green if ≤2, yellow if ≤5, red if >5
  evidence = "{todo_count} items in {loc} lines"

Health Score:
  value = weighted average of all dimensions
  display = "{value}/100"
  color = green if ≥70, yellow if ≥40, red if <40
  evidence = "composite of {N} dimensions"

AI Cost:
  value = callsites with optimization opportunity
  display = "{value} opportunities"
  color = green if =0, yellow if ≤3, red if >3
  evidence = "{value} frontier model callsites for simple tasks"
  (only generate if LLM calls detected)
```

### Phase 3 — Generate SVG Badges

Generate each badge as a standalone SVG file using shields.io flat style:

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="{total_width}" height="20">
  <linearGradient id="b" x2="0" y2="100%">
    <stop offset="0" stop-color="#bbb" stop-opacity=".1"/>
    <stop offset="1" stop-opacity=".1"/>
  </linearGradient>
  <clipPath id="a">
    <rect width="{total_width}" height="20" rx="3" fill="#fff"/>
  </clipPath>
  <g clip-path="url(#a)">
    <rect width="{label_width}" height="20" fill="#555"/>
    <rect x="{label_width}" width="{value_width}" height="20" fill="{color}"/>
    <rect width="{total_width}" height="20" fill="url(#b)"/>
  </g>
  <g fill="#fff" text-anchor="middle" font-family="Verdana,Geneva,DejaVu Sans,sans-serif" font-size="11">
    <text x="{label_x}" y="15" fill="#010101" fill-opacity=".3">{label}</text>
    <text x="{label_x}" y="14">{label}</text>
    <text x="{value_x}" y="15" fill="#010101" fill-opacity=".3">{value}</text>
    <text x="{value_x}" y="14">{value}</text>
  </g>
</svg>
```

Color values:
- Green: `#4c1` (good)
- Yellow: `#dfb317` (warning)
- Red: `#e05d44` (critical)
- Blue: `#007ec6` (info — for last scan date)

**SVG generation rules:**
- Label width calculated from text length (approximately 6.5px per character + 10px padding)
- Value width calculated from text length (approximately 6.5px per character + 10px padding)
- Total width = label width + value width
- Text centered in each section
- Font: Verdana 11px (shields.io standard)

## Key Principles

1. **Real metrics** — every badge value comes from a scan, not a guess
2. **Evidence trail** — each value has a source command and count
3. **Honest colors** — red means red, don't inflate scores
4. **Static SVG** — badges are files in the repo, no external service dependency
5. **shields.io compatible** — same visual style developers already trust
6. **Refresh on re-run** — run the skill again to update values
7. **Zero dependencies** — generates SVG files, doesn't install badge services

## What This Skill Is NOT

- Not a live monitoring dashboard — badges show scan-time values
- Not shields.io — generates local SVG files, no external API
- Not a CI badge — doesn't connect to CI pipelines (use native CI badges for that)
- Not inflated — if test coverage is 6%, the badge says 6% in red
